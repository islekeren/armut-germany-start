# ARM-41/42 upload security

User authorized implementation on a separate branch; ARM-43 is excluded.

1. Add upload records with owner, folder, status, reserved bytes and expiry. Reserve daily/lifetime quotas under a database user-row lock; count failed attempts against the daily allowance.
2. Validate images by decoding with pixel limits and re-encoding; parse PDFs. Normalize extensions. Bound multipart bytes per folder, aggregate bytes, fields, parts and files before buffering.
3. Store documents/messages and quarantine in a separate private bucket, failing closed when configuration is absent. Return keys for private references; issue five-minute signed reads only for an owner/admin (documents) or a conversation participant (messages).
4. Presign only quarantine keys with a short expiry. Finalize by claiming the pending record, reading a bounded stream, validating and writing a new immutable destination object. Never return a public URL before validation. Reject expired/replayed/foreign attempts.
5. Validate message/document associations against ready records owned by the caller. Add authenticated frontend helpers for reads and finalization.
6. Run unit, middleware, database/S3 integration, authorization, lint, type and build checks. Document production bucket/CDN and legacy-object migration checks separately; production credentials are not available here.

Limits: profiles 5 MiB, other images 10 MiB, documents 20 MiB, aggregate multipart file data 30 MiB; 100 reservations and 200 MiB per account per rolling 24 hours, 1 GiB live storage. Private bucket lifecycle must expire quarantine after one day. These are technical abuse limits, not legal retention periods.

All implementation steps completed. Independent review fixes and final validation are recorded in docs/UPLOAD_SECURITY.md. ARM-43 code is untouched. Production storage policy, URL-expiry and legacy migration checks remain operational rollout requirements; no production deployment or main merge was performed.
